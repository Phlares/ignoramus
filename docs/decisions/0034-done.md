# 0034 A done record ends a study

Date: 2026-11-15. Decided and built.

A finished study still accepted `run`, and each run appended session records. No signed record said that a study had ended, how, or when.

Decision:

- **The record.** A signed record of kind `done` ends a study. Its body is `{"end": ..., "ended_at": ..., "by": {"seq": ..., "hash": ...}}`.
- **The ends.**
  - `rows`: every admitted row ran and the study is finished, as 0025 defines it. `ended_at` is the card's finish time.
  - `resize-stop`: the same, and the `resize` record's decision is not `continue`.
  - `stop`: the log holds a `stop` record. `ended_at` is that record's time.
- **`by`** names the record that met the end. For `rows` and `resize-stop` it is the last estimate or verdict record the analysis counts, else the analysis record. For `stop` it is the `stop` record. When a study is both finished and stopped, the end whose `by` record comes first in the log wins.
- **Two times.** The record's own `ts` is when it was written. `ended_at` is when the end was met, and it can be much earlier. It can also be later than the `by` record's time, by the close of the stream slot: that close is in the stream log, not in the study's log.
- **One write site.** One `close` step appends `done` when an end holds and the log holds no `done`. It decides and appends under the log's lock, so a second call adds nothing.
  - `run` and `resume` call it last, after their `session.end`.
  - `stop` on an idle study calls it after the stop trace.
  - Only a holder of the run lock writes the stop trace or `done`. A run holds the lock until its `session.end` and its `done` are written, so no `stop` from elsewhere puts `done` before that `session.end`.
- **Repair.** A crash between `session.end` and `done` leaves a finished study without `done`. The next `run` adds a session, then `done`, and nothing else. A study finished by an older box gets its `done` the same way; it needs `--box-changed` when the binary differs. A crash between the stop trace and `done` leaves a stopped study without `done`. `run` refuses a stopped study, and that stays. A second `stop` adds only `done`, and prints that the first stop's reason stands. When `done` cannot be written after a stop, the stop still succeeds and prints "the done record is not written: …; run stop again".
- **After `done`.** `run`, `resume`, `stop` and `pause` refuse with `E-DON-001` before any write: no session record, no control file, no state file.
  - `stop` reads the log before it sends its request. A log that reads and holds `done` refuses, and nothing is written. A log that cannot be read still gets the request, so a torn log cannot hide a stop from a live run.
  - A run can write `done` while a stop is being sent. `stop` then reports "the stop request is sent, but the study ended first; the request is cleared", with no rule code. The stop trace checks for `done` under the log's lock and appends no `stop` record after it. A stop request found pending on a done study is cleared.
  - A run that the binary gate refuses writes nothing, unless a stop is pending. The stop trace is always written, and the lock holder that writes it closes the study.
- **Two stop fixes.** A `stop --reason`, `run --box-changed` or `resume --box-changed` value that is empty or only white space is refused before anything is written (#106). The stop deviation takes its row total from the rows that run, not from the schedule, so a stop after the last row that runs reads `after-collection-before-access` (#107).
- **What may follow.** `stamp` records (0033) and `opened` records (0025) may follow `done`. Nothing else may. `verify` fails on any other record after `done`, and on a second `done`.
- **Where the end shows.** `verify` prints the end, its time and the `done` record's seq, or "no done record". `status` prints the end and its time; `status --json` shows it under the key `ended`, since `done` there already counts the rows done. The card prints "Study ended" with the end, `ended_at` and the `done` record's seq and hash, or "no done record" for an older study.
- **No unlock.** No verb removes or reopens a `done` study. A correction is a new study that names the original.
- **No `finish` verb.** The box writes `done` when an end holds. Nobody has to call a verb for it.

Why:

- A closure record holds dated tasks and who did them, and shows that edit access ended at one definite time. A final lock should be final (SCDM). The `done` record is that time, signed, inside the chain.
- A trial's completion date is the date of the last data collection for its outcome, whether the trial ran to protocol or was terminated (42 CFR 11.10). So `ended_at` sits beside the record's own `ts`, and a stopped study gets an end and a date too.
- The steps that finalise data before analysis are confirmed and documented under pre-specified procedures (ICH E6(R3)). The ends are fixed in the box, the same for every study, and need no call from anyone.
- One write site, after `session.end`, makes `done` the last record of the run that ended the study. Two write sites, one where the analysis finishes and one in the stop, would put that run's `session.end` after `done`.
- `stop` and `pause` refuse too, so no verb leaves a control file or a record on a study whose end is fixed.

Case against:

- SCDM allows an unlock with documented authorization, for an error that could change the analysis, and sends other errors to a log. The box has neither. An error found after `done` needs a whole new study, and no error note can follow `done` yet.
- A `finish` verb would make the end an act that someone performs, as a closure checklist records who did each task. We rejected it: a person or a script must remember to call it, and a study left unfinished by a missing call accepts more runs.
- When a stop follows complete results, the end is `rows`, and `done` does not carry the stop's reason. The reason stays in the `stop` record.
- `stop` on a done study fails. A script that stops every study it started must treat that refusal as success.

Limits:

- A stopped confirmatory study gets `done` while its stream slot stays open, and later levels in the stream do not change. Online control of the false discovery rate with e-values logs a decision for every slot, non-discoveries included (e-LOND). Closing that slot is a separate issue.
- A stopped study has no card: `report` still refuses it (0025). `status` and `verify` show its end.
- `done` states the end the box computed from the log. It does not say that a person reviewed the study.
- A study finished by an older box gets `done` only through one more run, which adds a session and, when the binary differs, a box-changed deviation row.

What failure this prevents: a finished study that still accepted a run. `run` on a finished study appended session records, and no test covered it. Observed in the code, not in a study.

Constants: none. The record sets no value.
