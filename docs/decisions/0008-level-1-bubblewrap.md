# 0008 Level 1 through bubblewrap

Level 1 runs each row in a bubblewrap sandbox. bubblewrap is the first level 1 launcher. We evaluate it later against a launcher of our own (issue #2). It sits behind the `Backend` trait, so a replacement touches one module.

Decision:

- Launcher: bubblewrap 0.8 or later, found on `PATH`; 0.8 added `--disable-userns`. It is audited, runs without privileges on a kernel with user namespaces, and is small: one C program, the sandbox that Flatpak uses. The box records `bubblewrap <version>` as the launcher in the `run.start` event and in every row record, next to the isolation level.
- Isolation arguments, one builder for every sandbox: `--unshare-user --unshare-ipc --unshare-pid --unshare-net --unshare-uts --unshare-cgroup --disable-userns --die-with-parent --new-session --clearenv --seccomp <fd> --json-status-fd <fd>`, then `--proc /proc`, `--dir /dev` with `--dev-bind` of `/dev/null`, `/dev/zero` and `/dev/urandom` only, and last `--remount-ro /`. There is no `/tmp`.
- Binds: the environment root's `usr`, `bin`, `lib`, `lib64` and `etc`, each when present; a folder is bound read-only and a symbolic link is made again with the same target. The input folder is `/in` (read-only), the output folder is `/out` (the only writable path), and the payload's folder is `/payload` (read-only). The payload starts in `/out` with `IGNORARIUM_IN=/in` and `IGNORARIUM_OUT=/out` and the job's own variables, nothing else.
- Descriptors: bubblewrap inherits only the seccomp pipe and the status pipe, besides null standard input and its output pipes. Before it starts bubblewrap, the box's child marks every other descriptor close-on-exec with `close_range`. Level 1 therefore needs Linux 5.11 or later, which added `CLOSE_RANGE_CLOEXEC`; the probe names the kernel when the call fails.
- Exit: bubblewrap writes the payload's exit code on the status pipe. An exit code means the payload ran: 0 is a success, any other code is a payload result. No exit code means the sandbox failed to start: the row is an infrastructure fault with the last 4 KiB of bubblewrap's error output. Timeout and stop kill bubblewrap's process group, as at level 0.
- Process lifetime: each sandbox has its own PID namespace. When its PID 1 dies, the kernel kills every process in it, so a payload that detaches with `setsid` dies with the row. PID 1 dies with bubblewrap (`--die-with-parent`), and bubblewrap dies with the box.
- WSL interop: a Windows program in `/in` cannot run from the sandbox. WSL starts Windows programs through `binfmt_misc` handlers named `WSLInterop` (and others with that prefix, such as `WSLInterop-late`), whose interpreter is `/init`. For a handler registered without the `F` flag (WSL's default `P`), the kernel looks up the interpreter in the root of the process that runs the program. The sandbox root holds only the bound folders, so the interpreter is not there and the run fails. With `F`, the kernel opened the interpreter when the handler was registered, so a program in the sandbox could start Windows programs outside it. The probe reads every `WSLInterop` entry: one that is enabled with `F`, or one it cannot read, makes level 1 unavailable, with that reason. A disabled handler, no such entry, or `binfmt_misc` not mounted is fine. Other handlers, such as qemu-user, run their interpreter inside the sandbox and are not checked.
- Seccomp filter, compiled on the host with `seccompiler` and handed to bubblewrap on a pipe: `io_uring_setup`, `io_uring_enter`, `io_uring_register`, and `socket` with `AF_VSOCK` as its first argument, each fail with `EPERM`. Every other call is allowed; v0 payloads are our own. io_uring is a large kernel attack surface. A vsock socket reaches the hypervisor or host, a path the network namespace does not cut. The filter is built for x86_64 and aarch64.
- Foreign system call ABIs: the filter checks the architecture tag first and kills the process on a mismatch. A 32-bit call, `socketcall` among them, is killed that way. The x32 ABI of x86_64 uses the x86_64 tag with bit 30 set in the call number, so the filter denies the x32 numbers of the four denied calls too. Residual: the filter is a deny list. It allows every other x32 call, as it allows the native one, so a call denied later needs its x32 number as well.
- Self-test, before every row: a sibling sandbox runs the box's hidden `dev selftest` verb. It is built by the same isolation builder, with the host root and the box binary bound so the binary can load; an environment root may lack the host libraries it needs. It checks three things: `/proc/net/dev` lists no interface but `lo` and a TCP connect to port 9 of a documentation address (TEST-NET-1, RFC 5737) fails within 1 s; an `AF_VSOCK` socket fails; `io_uring_setup` fails. `EPERM` counts as denied; `ENOSYS` or `EAFNOSUPPORT` counts as blocked because the kernel lacks the feature; any other result leaves the call open. A failed self-test never runs the payload: the row is an infrastructure fault, `sandbox self-test failed: …`. It is retried like any such fault; when the retries run out, the row is voided and the run pauses. The self-test's time counts against the row's wall time and its CPU adds into the row. Its result goes into a `sandbox.selftest` event. A launcher of our own could run the self-test inside the payload's own sandbox.
- Probe: level 1 is unavailable, with the reason, when the kernel lacks `CLOSE_RANGE_CLOEXEC`, an enabled WSL interop handler has the `F` flag or one cannot be read, bubblewrap is missing or older than 0.8, or a test sandbox on the host root fails, for example because user namespaces are blocked. `machine.toml` then gets `max_level = 0`, and a study with `min_isolation = 1` is refused with the level the machine reaches; `ignorarium probe` prints why. The box never falls back to a lower level by itself.
- Environment: an empty `pins.environment` builds the recipe in `<study>/env/` when one is present, or else runs on the host root. A non-empty pin is the store digest of a saved image, used as it is and refused when the store lacks it. Level 0 ignores environments.
- Environment root extraction: the saved image is extracted once into `store/rootfs/<digest>/`, and only the five bound folders are kept. A crash leaves a temp folder beside the result, never a partial tree at it.
  - One parser: the `tar` crate reads each archive header by header, and the box writes the tree itself. It never calls the `tar` program or the crate's unpack functions. A path with a root or `..` is refused. A file keeps only its permission bits, so no setuid, setgid or sticky bit survives. The box records every symbolic link and file it writes. It refuses a write through a link, and makes a hard link only to a file it wrote in a kept folder, reached through no link. Whiteouts apply as the OCI layer format defines them.
  - Formats: a plain tar is known by its `ustar` magic. A gzip layer is decoded in the process, with the pure-Rust backend of `flate2`, and read by the same parser. zstd, xz and bzip2 layers are refused as an unsupported compression.
  - Outer archive: the box reads it in two passes. The first stops at `manifest.json`. The second records where the data of each layer the manifest names lies, stops once it has them all, and records nothing else. The first regular file of each name counts; a link or a folder of that name does not, and a later copy is not read. `docker load` reads every entry, so it may pick a later copy. Each layer is then read from where it lies. A manifest may name at most 256 layers.
  - Budget: 32 GiB per extraction. Every byte read from the archive counts: in the two passes over the outer archive, and in the two passes over each layer (whiteouts first, then content). So does every byte decoded from a gzip layer, since a decoder can read many bytes that decode to nothing, and 4 KiB for each entry written, the parent folders a path implies included. One count bounds the data, the decoding work and the entry count. The outer archive is read up to twice and each layer twice more, so an archive whose manifest comes last, as `docker save` writes it, fits about 8 GiB of plain layer data. A gzip layer costs four times its compressed size and twice its decoded size. Fewer than 8 million entries fit.
  - Memory: the box keeps the path of every file and link it writes. A second count charges the bytes of each path it records; past 256 MiB the extraction fails and publishes nothing.
  - Header fence: after the reader yields an entry, it may read that entry's stored data, padded to 512-byte blocks, and 1 MiB more before it yields the next one. This bounds the memory held by long names, long link names and PAX records, in the outer archive and in every layer.
  - A GNU sparse entry (type `S`) is refused: the reader reports its expanded size, which would move the fence past data the archive does not hold. Image layers do not use them. A PAX-format sparse file (`GNU.sparse.*` records) is a regular entry to the parser: the box writes its stored bytes, the sparse map included, so the fence holds, but the file is not the expanded file.
- Subreaper: the first level 1 sandbox, from a probe or a row, makes the box process a child subreaper for the rest of its life. `ignorarium probe` starts one. bubblewrap leaves the sandbox's PID 1 unreaped, and the box must reap it to count the payload's CPU. Every orphan of the box's descendants then becomes the box's child; nothing reaps those, so they stay zombies until the box exits. An embedder of the library sees the same.
- Reap limit: the box waits at most 5 s for the sandbox's PID 1 once bubblewrap is gone, so a payload stuck in uninterruptible sleep does not hold the box. Past the limit, that PID 1 stays a zombie of the box until the box exits. There is no sweep that waits on every child: it would take other children's exit status.
- Unknown CPU: when the box cannot read a row's CPU, the row is charged the larger of the CPU it saw and the row's estimate. The box writes a `row.cpu_unknown` warning event, counts the row in the status, and pauses the run at the next row boundary, as for any meter that cannot read.

Limits:

- No Landlock. bubblewrap has no Landlock option, and a Landlock ruleset set before bubblewrap starts would forbid bubblewrap's own mounts. The write fence at level 1 is the read-only root and binds with one writable `/out`. Landlock returns with the launcher evaluation.
- A sandbox shares the host kernel. A kernel bug can break the sandbox; level 2 runs a separate kernel per row (0010).
- No CPU or memory caps beyond the row's wall time. The CPU of a row killed at timeout or stop, and of any process still running when the payload exits, is lost: the kernel reaps the killed sandbox's processes without adding their time to any count the box reads. A cgroup reading is on issue #2.
- Stale temp folders after a crash stay in the store; their cleanup is on issue #2.
- AppArmor: Ubuntu restricts unprivileged user namespaces through AppArmor (added in 23.10, on by default since 24.04), so bubblewrap fails there without a profile. On a long-lived host, give bubblewrap a per-binary AppArmor profile that allows user namespaces. Turn the restriction off with `sysctl kernel.apparmor_restrict_unprivileged_userns=0` only on a throwaway machine; CI runners do this.

Why: bubblewrap gives a working level 1 now, from a small and audited program, without root. The self-test checks on every row that the sandbox still holds on this host, so a broken sandbox costs a paused run, not an unisolated row. Every image byte passes through one parser and one budget, so a crafted image cannot write outside its tree or exhaust the disk or the memory.
